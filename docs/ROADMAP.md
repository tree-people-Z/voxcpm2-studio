## 已做

- **生成可中断**：`should_stop` 每块检查；界面「停止合成」；关窗前先取消再等。
- **真进度**：状态行显示「第 N/M 段 · 已生成 X.Xs」。
- **本地 API + MCP**：`voxcpm_studio/api.py`（HTTP）、`tools/tts_mcp_server.py`（5 个工具）；
  与界面共享引擎与"忙"判断，界面在生成时 API 返回 409。
- **torch.compile 探测**：缺 triton / 非 CUDA 时提前跳过并说明原因，避免官方那段无用 warmup。
- **默认参数质量优先**：`cfg_value=3.0`、`inference_timesteps=30`（官方区间上界，慢约 2.2 倍）。
- **窗口最小尺寸 960×600**：1366×768 笔记本能放下，更小时两列各自滚动。
- **纯函数测试**：`tests/test_core.py`，覆盖切分 / 描述组合 / 配置往返 / API 参数校验。

## 明确不做（以及理由）

| 事项 | 为什么不做 |
|---|---|
| 历史记录落盘 | 用户可直接翻 `outputs/` 目录，加持久化只是多一份状态要维护 |
| 生成失败时保留上一次结果 | 同上，且失败是少数路径，代价（多一套状态回滚）不划算 |
| 分段拼接处加淡入淡出 | **实测伪需求**：模型输出自带静音边距（段首 30ms 峰值 0.0002、段尾 0.0000），直接 `concatenate` 不爆音 |
| 多 take 对比 | 再点一次「开始合成」即可 A/B，不值得加一套列表 UI |
| `mainwindow.py` 拆包 | 纯重构、零用户价值、改动面最大 |
| 日志落盘 | 出问题可直接跑脚本复现，不需要用户回传日志 |
| 波形点击定位 / 参考音频裁剪 | 锦上添花；整段播放已够用 |
| 打包 exe + 依赖锁定 | 只有要分发给别人时才需要 |
| API 增强（OpenAPI / SSE / 队列） | 现在 `curl` 与 MCP 都能调通，够用 |
| 自动转写（极限克隆免手打） | 需额外 ASR 模型，收益不确定 |
| 主题热切换 | 只是"改完要重启"，不值得为此改掉图标着色的设计 |
| 可访问性 / 跨平台 | 单人本地工具，投入产出比低 |

## 如果哪天要做

按这个顺序，且都先量测再动手：

1. **打包**（PyInstaller onedir + 模型外置）——只在你需要给别人用时。
2. **性能**——先对比「步数 10」「triton-windows + torch.compile」「Nano-vLLM 后端」，
   用同一文本 5 次取中位数，RTF 改善 ≥15% 且音质无退化才采用；8GB 卡注意 CUDA Graph 的显存。
3. **多 take 对比**——如果确实经常"生成三次挑一个"，再做。
